# Will of Steel — v0.1.0 combat prototype

The protagonist is William.

Original mobile portrait sword-dueling project. Uses Three.js r180 via dynamic ES-module CDN imports; no npm installation or build required. This is a source prototype, not a production release.

## Run

From this folder, run `npm run serve` (requires Python 3) or `python3 -m http.server 8080`, then visit `http://localhost:8080`. To try it on an iPhone on the same network, open the computer's LAN IP on port 8080; firewall settings may need adjustment. Alternatively host these files on a static HTTPS site such as GitHub Pages. Internet access is needed for Three.js; a WebGL2-capable browser is required. Do not open index.html directly from a file manager because ES module security rules may block imports.

Right thumb: swipe in the circular gesture area to cut; hold still for 330 ms to thrust. Left thumb: hold PARRY to enter defense; right-thumb directions change your guard. Release the left thumb and attack during an opening. On desktop, use arrow keys for directions, Enter for thrust, and Space (hold) for parry. Choose a training bout or standard challenge on the starting screen.

## Verification

`npm test` runs 10 deterministic unit tests without installing dependencies. `node --check main.js` checks syntax. Both passed in the development environment. The environment could not resolve the npm registry or download Three.js. The live 3D rendering, CDN availability, mobile touch input, audio, thermal behavior and physical-device performance have not been verified. The UI displays an explicit load error if the engine fails. No hosted preview has been deployed.

## Architecture

- `combat.js`: independent combat rules and gesture mapping; seeded AI; damage and stamina; guard and ripostes.
- `main.js`: procedural scene, character and sword meshes, camera, pose animation, HUD, touch/keyboard input and synthesized feedback.
- `index.html`, `style.css`: responsive portrait screens and controls.
- `tests/`: combat rule regression tests.

## Known limitations

- Combat strikes and blade clashes are resolved by timing/guard state rather than actual 3D contact detection. Meshes and animation are placeholders; no skeletal rig, true two-hand IK, footwork simulation, authored assets, spatial audio or physical hit zones yet.
- The branching introduction is a two-option prototype (training versus challenge); no persistent narrative, inventory or progression.
- Gesture thresholds and difficulty values are initial tuning guesses. The physical iPhone test must determine reachability, direction recognition, input latency, and frame rate.
- Working title, opponent, courtyard location and sample text are provisional; no unapproved campaign decisions have been made.
